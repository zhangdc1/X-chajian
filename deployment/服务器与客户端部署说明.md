# XBot 服务器与客户端部署说明

## 一、部署结构

推荐拆成两类机器：

- 中央服务器：运行中央控制器、Discord Bot、Scheduler。
- 客户端电脑：运行 Worker、GUI、比特浏览器和真实自动化任务。

客户端主动访问中央服务器拉任务、上传心跳、上传账号、上传执行结果。中央服务器不需要主动连客户端，所以客户端在公司内网也可以工作，只要它能访问服务器的 `8766` 端口。

## 二、打包

在开发机项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/package_release.ps1
```

输出：

```text
release/xbot-controller_时间.zip
release/xbot-worker_时间.zip
```

注意：打包脚本不会打包当前运行数据库、日志、任务审计、缓存和 pyc 文件。

## 三、中央服务器安装

### 1. 上传并解压

把 `xbot-controller_时间.zip` 上传到服务器，例如：

```text
D:\xbot-controller
```

### 2. 安装 Python 和依赖

服务器安装 Python 3.10+，然后执行：

```powershell
cd D:\xbot-controller
python -m pip install -r deployment/requirements-controller.txt
```

### 3. 准备 token

生成一个长 token，后面中央、Discord Bot、Scheduler、所有 Worker 都必须一致，例如：

```text
xbot-prod-2026-请换成更长随机字符串
```

### 4. 启动中央控制器

```powershell
cd D:\xbot-controller
powershell -ExecutionPolicy Bypass -File deployment/start_controller.ps1 -HostName 0.0.0.0 -Port 8766 -Token "你的中央token"
```

开放服务器防火墙和云安全组：

```text
TCP 8766
```

外网检查：

```powershell
Invoke-RestMethod http://服务器公网IP:8766/health
```

看到 `ok: true` 即中央控制器在线。

## 四、部署 Discord Bot 和 Scheduler

在中央服务器复制配置模板：

```powershell
Copy-Item discord_config.example.yaml discord_config.yaml
Copy-Item scheduler_config.example.yaml scheduler_config.yaml
```

编辑 `discord_config.yaml`：

```yaml
discord_token: "你的Discord Bot Token"
central_api: http://127.0.0.1:8766
central_token: 你的中央token
proxy: ""
allowed_user_ids: []
```

编辑 `scheduler_config.yaml`：

```yaml
central_api: http://127.0.0.1:8766
central_token: 你的中央token
scheduler_interval_seconds: 30
dispatch_limit: 100
```

如需自然语言识别、Grok 输出智能结构化、智能评论，在中央服务器复制并编辑：

```powershell
Copy-Item model_config.example.yaml model_config.yaml
```

把 `enabled` 改成 `true`，并填写你的 OpenAI-compatible `base_url`、`api_key`、`model`。

启动：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/start_discord_bot.ps1
powershell -ExecutionPolicy Bypass -File deployment/start_scheduler.ps1
```

生产环境建议用 systemd/Windows 计划任务/NSSM 保活，Discord Bot 只保留一个实例。若 Discord 回复重复，先检查并清理旧进程：

```bash
ps aux | grep "automation/discord_bot.py"
pkill -f "automation/discord_bot.py"
systemctl restart xbot-discord
```

新版 Bot 启动时会创建 `discord_config.discord_bot.lock`，发现已有实例会自动退出，避免重复回复。

## 五、客户端电脑安装

### 1. 解压客户端包

把 `xbot-worker_时间.zip` 解压到每台公司电脑，例如：

```text
D:\xbot-worker
```

### 2. 安装依赖

```powershell
cd D:\xbot-worker
powershell -ExecutionPolicy Bypass -File deployment/install_worker_deps.ps1
```

### 3. 配置 Worker

```powershell
Copy-Item automation_config.example.yaml automation_config.yaml
```

编辑 `automation_config.yaml`：

```yaml
node_id: PC-01
label: 公司电脑01

central_api: http://服务器公网IP:8766
central_token: 你的中央token

bit_api_url: http://127.0.0.1:54345
sync_group_ids:
  - "你的比特浏览器分组ID"

worker_enabled: true
max_concurrency: 1
enable_grok_browser: true
require_license: false
```

每台电脑必须改不同的 `node_id`，例如 `PC-01`、`PC-02`、`PC-03`；`label` 也要写成对应且容易识别的名称，例如 `Office PC 02`，否则 Discord 电脑状态里会看起来像旧电脑。

如果客户端需要智能评论本地生成，也复制模型配置：

```powershell
Copy-Item model_config.example.yaml model_config.yaml
```

首次使用 GUI 或原脚本模式前，复制 GUI 参数模板：

```powershell
Copy-Item config.example.yaml config.yaml
```

然后打开 GUI 填分组、窗口数、发帖素材路径等参数并保存。

### 4. 启动 Worker

确保本机比特浏览器已启动，并且本地 API 是：

```text
http://127.0.0.1:54345
```

启动：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/start_worker.ps1
```

## 六、GUI 面板

客户端本地打开 GUI：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/open_panel.ps1
```

GUI 中可以查看/修改：

- 基础参数
- 账号评分计划
- 中央评分提示词
- 计划任务状态
- 本地运行日志

## 七、验证链路

在中央服务器检查 Worker：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/check_local_services.ps1 -Token "你的中央token"
```

Discord 群里测试：

```text
@X-bot 查看电脑状态

@X-bot 账号评分 测试
@X-bot 查看账号计划 测试
@X-bot 模式一 测试
```

## 八、外地服务器与公司客户端如何交互

交互方向是：

```text
客户端 Worker -> 中央服务器
```

Worker 会定时：

- 上传心跳
- 同步比特浏览器账号
- 拉取待执行 job
- 上传日志、结果、失败原因

中央服务器负责：

- 接收 Discord 指令
- 创建任务
- 保存计划和调度
- 等 Worker 主动来领取任务

因此公司内网不需要做端口映射；只要公司电脑能访问服务器公网 IP 的 `8766` 端口即可。

## 九、常见问题

### 401 Unauthorized

中央、Worker、Discord Bot、Scheduler 的 token 不一致。统一检查：

```yaml
central_token: 你的中央token
```

### WinError 10061

目标端口没人监听或被防火墙拦截。检查：

- 中央控制器是否启动
- 服务器安全组是否开放 `8766`
- 客户端 `central_api` 是否填了公网 IP

### 账号同步不到

检查客户端：

- 比特浏览器 API 是否开启
- `bit_api_url` 是否正确
- `sync_group_ids` 是否填写了真实分组 ID

### 关闭窗口服务就停了

这是正常的。生产环境需要用 Windows 计划任务、NSSM、PM2 或 systemd 做后台保活。
