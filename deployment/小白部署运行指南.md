# XBot 自动化系统小白部署运行指南

这份指南按“照着做就能跑”的方式写。你不用理解代码结构，先跑通，再慢慢调参数。

## 0. 你会得到什么

系统分成 4 个程序：

1. **中央控制器**：总调度中心，负责存账号、任务、计划。
2. **本地 Worker**：每台有比特浏览器的电脑都跑一个，负责执行中央派来的任务。
3. **Discord Bot**：放进 Discord 群里，你 @ 它下命令。
4. **Scheduler 调度器**：把已确认的计划按时间派发给 worker。

现有人工 GUI 脚本不变。你仍然可以在每台电脑上手动打开原来的 `newkami.py` / `newtkmain.py`。

## 1. 推荐部署方式

推荐：

- 选一台稳定电脑或服务器做“中央控制电脑”。
- 所有跑比特浏览器的电脑都做“Worker 电脑”。
- Discord Bot 和 Scheduler 可以跟中央控制器放在同一台电脑。

如果你现在只有一台电脑，也可以全部跑在同一台电脑上。

## 2. 安装 Python

每台电脑都需要安装 Python 3.10 或以上。

1. 打开 https://www.python.org/downloads/
2. 下载 Windows 版本 Python。
3. 安装时一定勾选 **Add Python to PATH**。
4. 安装完成后打开 PowerShell，输入：

```powershell
python --version
```

能看到版本号就说明成功。

## 3. 安装依赖

进入项目目录：

```powershell
cd D:\比特x养号_2
```

中央控制电脑安装：

```powershell
python -m pip install -r deployment/requirements-controller.txt
```

Worker 电脑安装：

```powershell
python -m pip install -r deployment/requirements-worker.txt
```

也可以直接运行：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/install_worker_deps.ps1
```

如果同一台电脑既做中央又做 worker，两条都执行。

## 4. 配置中央控制器

你需要准备一个很长的密钥，自己随便生成，比如：

```text
my-xbot-token-2026-change-this
```

后面所有配置里的 `central_token` 都要填同一个。

启动中央控制器：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/start_controller.ps1 -Token "my-xbot-token-2026-change-this"
```

看到类似下面内容说明启动成功：

```text
central controller listening on http://0.0.0.0:8766
```

不要关闭这个窗口。

本机测试：

```powershell
Invoke-RestMethod http://127.0.0.1:8766/health
```

能看到 `ok: True` 就说明中央控制器正常。

## 5. 配置 Worker 电脑

每台有比特浏览器的电脑都做一次。

复制配置模板：

```powershell
Copy-Item automation/config_example.yaml automation_config.yaml
```

打开 `automation_config.yaml`，重点改这些：

```yaml
node_id: PC-01
label: 工作室电脑01

central_api: http://中央控制电脑IP:8766
central_token: my-xbot-token-2026-change-this

bit_api_url: http://127.0.0.1:54345
sync_group_ids:
  - "你的比特浏览器分组ID"

worker_enabled: true
require_license: false
enable_grok_browser: false
```

说明：

- `node_id`：每台电脑必须不一样，比如 `PC-01`、`PC-02`。
- `central_api`：如果中央和 worker 是同一台电脑，用 `http://127.0.0.1:8766`。
- `sync_group_ids`：填比特浏览器分组 ID，可以填多个。
- `require_license`：开发测试先用 `false`，打包发布再改成 `true`。
- `enable_grok_browser`：第一次部署先用 `false`，确认路由没问题后再开。

启动 worker：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/start_worker.ps1
```

不要关闭这个窗口。

## 6. 检查 Worker 是否连上中央

在中央控制电脑上执行：

```powershell
python automation/accounts_cli.py --central-api http://127.0.0.1:8766 --token "my-xbot-token-2026-change-this" list-accounts
```

如果 worker 已经同步到账号，会看到账号列表。

如果没有账号：

1. 确认比特浏览器已经打开，并且 API 地址是 `127.0.0.1:54345`。
2. 确认 `sync_group_ids` 是正确的分组 ID。
3. 看 worker 窗口有没有报错。

## 6.1 自动任务日志和审查文件

自动化任务运行时，会在本机生成这些文件：

```text
automation/logs/PC-01/job_任务ID_mode1_时间.txt
automation/tasks/task_audit.jsonl
automation/tasks/current_task.json
automation/output/comment_drafts.jsonl
```

说明：

- `logs/PC-01/...txt`：当前任务的完整本地日志。
- `task_audit.jsonl`：每个任务开始、结束、失败都会记录一行，方便审查。
- `current_task.json`：当前这台电脑正在执行什么任务；空闲时显示 `idle`。
- `comment_drafts.jsonl`：智能评论和回退评论都会留底。

模式一、模式二、模式三由 Bot 或调度器触发时，会自动打开原 GUI 风格的日志窗口。这个窗口只用于看日志，不影响你手动打开原程序填参数。

## 6.2 配置模型语义识别和智能评论

打开项目根目录的 `model_config.yaml`：

```yaml
enabled: true
provider: openai_compatible
base_url: "https://你的中转站或deepseek地址/v1"
api_key: "你的秘钥"
model: "deepseek-chat"
timeout_seconds: 30
temperature: 0.1

smart_comment:
  enabled: true
  auto_publish: true
  save_drafts: true
  fallback_to_comment_library: true
```

如果 `enabled: false`，固定命令仍然能用，只是不启用自然语言识别和智能评论生成。

智能评论开启后，模式一/模式二触发评论时会先读取帖子内容生成贴合主题的评论；模型失败会按配置回退到你的评论库，并同样写入 `comment_drafts.jsonl`。

## 6.3 账号评分计划

账号评分计划用于“每个账号单独问 X Grok，生成自己的权重提升计划，再自动转成定时任务”。

默认提示词来源：

```text
D:\比特x养号_2\账号评分提示词.txt
```

注意：

- 这个 txt 只作为中央控制器首次初始化提示词使用。
- 后续以中央控制器保存的提示词为准。
- 客户端电脑没有这个 txt 文件也没关系，Worker 会使用中央下发的提示词。
- GUI 的“账号评分计划”页可以查看和修改中央提示词。

Discord 常用命令：

```text
!账号评分 测试
!账号评分 测试 周计划
!查看账号计划 测试
!生成账号调度 测试
```

执行逻辑：

1. Bot 创建账号评分任务。
2. Worker 打开每个账号自己的 Bit profile。
3. Worker 进入 X Grok，并发送中央提示词。
4. 系统保存 Grok 原始回复，并转换成每天 5 个时间点的任务表。
5. Scheduler 到点派发任务，Worker 只执行对应单个账号。

## 7. 配置 Scheduler 调度器

复制配置：

```powershell
Copy-Item automation/scheduler_config_example.yaml scheduler_config.yaml
```

打开 `scheduler_config.yaml`：

```yaml
central_api: http://127.0.0.1:8766
central_token: my-xbot-token-2026-change-this

scheduler_interval_seconds: 30
dispatch_limit: 100
```

启动：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/start_scheduler.ps1
```

不要关闭这个窗口。

## 8. 配置 Discord Bot

### 8.1 创建 Discord Bot

1. 打开 Discord Developer Portal。
2. 新建 Application。
3. 进入 Bot 页面，创建 Bot。
4. 复制 Bot Token。
5. 打开 Bot 的 **Message Content Intent**。
6. 生成邀请链接，把 Bot 拉进你的群。

### 8.2 配置本项目

复制配置：

```powershell
Copy-Item automation/discord_config_example.yaml discord_config.yaml
```

打开 `discord_config.yaml`：

```yaml
discord_token: "你的Discord Bot Token"
command_prefix: "!"

central_api: http://127.0.0.1:8766
central_token: my-xbot-token-2026-change-this

allowed_user_ids: []
```

如果你的电脑访问 Discord 需要代理，在 `discord_config.yaml` 里加：

```yaml
proxy: http://127.0.0.1:7890
```

端口按你的代理软件实际端口填写，常见是 `7890`、`7897`、`10809`。

注意：这一行是写进 `discord_config.yaml` 文件里的，不是在 PowerShell 里输入的命令。

启动 Bot：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/start_discord_bot.ps1
```

看到 `Discord bot logged in as ...` 就说明成功。

如果同一条 Discord 指令被回复多次，说明服务器同时运行了多个 Bot。Linux 服务器执行：

```bash
ps aux | grep "automation/discord_bot.py"
pkill -f "automation/discord_bot.py"
systemctl restart xbot-discord
```

新版 Bot 会用锁文件阻止重复启动，但第一次升级前仍建议先清理旧进程。

## 9. Discord 里怎么用

### 9.1 当前 Bot 支持的命令

先确认你运行的是新版 Bot：

```text
!version
```

应该回复：

```text
当前运行版本: xbot-v2.1
```

如果不是这个版本，说明旧的 Bot 窗口还在运行。请先关掉旧的 `start_discord_bot.ps1` 窗口，再重新启动 Bot。

查看帮助：

```text
!help
```

查看电脑/worker 状态：

```text
!status
```

查看已同步分组和绑定别名：

```text
!groups
```

绑定分组别名：

```text
!bind 测试 4028808a9dddd516019df3bd0162204d
```

也兼容这种中文写法：

```text
@Bot A组 绑定 测试 4028808a9dddd516019df3bd0162204d
```

绑定后查询：

```text
!groups
```

查看账号：

```text
!accounts 测试
```

生成 Grok 计划任务：

```text
!plan daily 测试
!plan weekly 测试
!plan monthly 测试
```

查看任务：

```text
!jobs
!job detail 123
```

查看日志：

```text
!logs 123
```

查看 Grok 草稿计划：

```text
!plan draft 测试
!plan list 测试
```

把已经生成的 Grok 计划转换成每天的调度任务：

```text
!plan schedule 测试
```

确认计划并生成调度：

```text
!plan approve 123
```

查看调度：

```text
!schedule 测试
```

直接执行原脚本模式：

```text
!mode1 测试
!mode2 测试 url=https://x.com/xxx/status/123
!mode3 测试
```

说明：这些命令会读取现有 `config.yaml` 里的参数，只根据指令临时覆盖分组、模式二链接等信息，不会改变你本地人工打开 GUI 的使用方式。

### 9.2 分组别名

如果你不想每次输长 group_id，可以给分组起别名：

```yaml
!bind 测试 4028808a9dddd516019df3bd0162204d
```

以后可以直接：

```text
!accounts 测试
!plan weekly 测试
!plan list 测试
```

### 9.3 为什么生成计划后没打开浏览器

检查 worker 的 `automation_config.yaml`：

```yaml
enable_grok_browser: false
```

如果是 `false`，worker 只会模拟生成任务结果，不会打开比特浏览器，也不会进入 X/Grok。

要真正打开比特浏览器执行 Grok 采集，改成：

```yaml
enable_grok_browser: true
```

然后重启 worker：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/start_worker.ps1
```

再用：

```text
!状态
```

确认里面显示 `Grok浏览器=开启`。

查看电脑：

```text
@Bot 查看电脑状态
```

查看账号：

```text
@Bot 查看账号 分组=你的比特分组ID
```

生成 Grok 周计划任务：

```text
@Bot 生成Grok周计划 分组=你的比特分组ID
```

只让某台电脑执行：

```text
@Bot 生成Grok日计划 分组=你的比特分组ID 电脑=PC-01
```

查看草稿计划：

```text
@Bot 查看草稿计划 分组=你的比特分组ID
```

确认计划：

```text
@Bot 确认计划 plan=123
```

查看调度：

```text
@Bot 查看调度 分组=你的比特分组ID
```

## 10. 开启 X 内置 Grok 采集

第一次部署不要急着开。先确认：

1. 中央控制器正常。
2. worker 能同步账号。
3. Discord Bot 能创建计划任务。

确认没问题后，在对应 worker 的 `automation_config.yaml` 改：

```yaml
enable_grok_browser: true
```

然后重启 worker。

如果 Grok 页面打不开或读不到回复，通常是 X 页面元素变化了，需要调整：

```yaml
grok:
  input_selectors:
  send_selectors:
  response_selectors:
```

## 11. 使用现有卡密系统

开发测试阶段：

```yaml
require_license: false
```

正式发布前，在 worker 配置里改：

```yaml
require_license: true
card_number: "你的卡密"
```

本地 worker 会调用现有的卡密 API 登录和心跳，不启动原来的 GUI。

## 12. 打包 EXE

### 12.1 打包中央控制端

在中央控制电脑执行：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/build_controller.ps1
```

生成目录：

```text
dist\xbot-controller
dist\xbot-discord-bot
dist\xbot-scheduler
```

### 12.2 打包 Worker

在 worker 电脑或打包电脑执行：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/build_worker.ps1
```

生成目录：

```text
dist\xbot-worker
```

正式发给别人前，建议只发 worker 包，不发中央控制端源码。

## 13. 每次开机要启动哪些窗口

中央控制电脑：

1. 中央控制器
2. Scheduler
3. Discord Bot

Worker 电脑：

1. 比特浏览器
2. Worker

原来的人工 GUI 需要手动用时再打开，不冲突。

## 14. 常见问题

### Bot 没反应

- 检查 Discord Bot 窗口有没有报错。
- 检查是否打开 Message Content Intent。
- 检查 Bot 是否被拉进群。
- 试试 `!帮助` 或 `@Bot 帮助`。

### Bot 报 Cannot connect to host gateway.discord.gg

这说明 Bot 程序启动了，但电脑连不上 Discord 网关。一般是网络或代理问题。

先测试：

```powershell
Test-NetConnection gateway.discord.gg -Port 443
```

如果失败，在 `discord_config.yaml` 里配置代理：

```yaml
proxy: http://127.0.0.1:7890
```

然后重新启动：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/start_discord_bot.ps1
```

### Bot 报 PrivilegedIntentsRequired

说明 Discord 后台没有开启 Message Content Intent。

处理方法：

1. 打开 https://discord.com/developers/applications/
2. 选择你的 Application。
3. 左侧点 **Bot**。
4. 找到 **Privileged Gateway Intents**。
5. 开启 **Message Content Intent**。
6. 保存。
7. 重新启动 Bot。

### Worker 没账号

- 检查比特浏览器是否启动。
- 检查 `bit_api_url` 是否是 `http://127.0.0.1:54345`。
- 检查 `sync_group_ids` 是否填对。

### 报错 PyYAML is required

说明当前 Python 没安装读取配置需要的 PyYAML。运行：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/install_worker_deps.ps1
```

安装完成后重新启动 worker：

```powershell
powershell -ExecutionPolicy Bypass -File deployment/start_worker.ps1
```

### 中央连不上

- 同电脑用 `http://127.0.0.1:8766`。
- 不同电脑要用中央电脑的局域网 IP，例如 `http://192.168.1.10:8766`。
- Windows 防火墙要允许 8766 端口。

### 计划确认后没执行

- 检查 Scheduler 是否启动。
- 检查 `@Bot 查看调度 分组=xxx`。
- 检查 worker 是否在线。

## 15. 最小跑通顺序

按这个顺序最稳：

1. 启动中央控制器。
2. 启动一个 worker。
3. 确认能查到账号。
4. 启动 Discord Bot。
5. 在群里创建 Grok 计划任务。
6. 查看草稿计划。
7. 确认计划。
8. 启动 Scheduler。
9. 查看调度和 worker 日志。
